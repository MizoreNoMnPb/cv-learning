# 分类同步与中文分支生成

在 `master` 增删分类、调整论文归档或修改目录对照后，按本文同步导航并生成 `zh`。两个分支的正文都使用中文，生成器只转换分类路径和相应引用。

## 同步内容

1. 将现有分类登记到 [目录对照表](path-glossary.md)，填写唯一的 `id`、`English` 和 `zh-dir`。同名目录按父分类分别映射；删除分类时移除对应行。
2. 更新 [学习路径](../learning-path.md)、相关问题总览和占位说明。分别标明已有正文、阅读草稿、仅有论文、待编写；不要把已有原文的目录写成空目录。
3. 按 [论文归档规范](paper-unit.md)为新增原文补齐 `sources.md`。核对 PDF 本身的版本；目录名与正式出版信息有差异时，在书目中说明。
4. 修复被移动或删除内容的相对链接。撤下论文归档后，删除“已归档”清单中的对应条目；正文中的有效学术引用可以保留。

## 检查与生成

在仓库根目录运行：

```sh
python agent/generate-zh.py --check
python -m unittest discover -s agent/tests -v
```

`--check` 检查现有分类是否登记，以及受 Git 管理或尚未忽略的 Markdown 文件中，本地内联链接的目标路径是否存在。链接形式包括 `[标题](路径)`、图片链接和 `[标题](<带空格的路径>)`。该检查不核验外部网址、页内锚点或参考式链接，也不判断论文事实是否正确。

不带参数运行时只预览目录转换。先检查差异并提交 `master`，再生成中文分支：

```sh
python agent/generate-zh.py --apply
```

生成器要求当前分支是 `master`、工作区干净，且 `zh` 未在其他工作树中检出。它从当前 `master` 提交创建临时工作树，转换分类路径、重写链接并检查结果；成功后更新本地 `zh`。当前工作区仍停留在 `master`。生成失败时，`zh` 保留原来的提交。

`zh` 的生成提交直接以本次 `master` 为父提交，不累积旧的生成历史。因此后续发布 `zh` 时可能需要带预期旧提交值的 `--force-with-lease`；首次发布空远程不需要强制推送。脚本只更新本地分支，不负责发布。

## 完成标准

- 现有分类均已登记；已删除分类不会重新创建。
- 中文路径按父分类映射，论文目录名、Markdown 文件名及 PDF 内容保持原样。
- 两个分支中受检查的本地链接均能找到目标。
- `zh` 的 README 标明本次来源提交；`master` 的提交和工作区未被生成过程改动。
- 忽略的草稿和编辑器文件不会进入生成分支。

`agent/`、`read-paper-skill/` 和 `fork-profile.md` 中的目录规范以 `master` 为准，其中的代码示例与对照表保留英文路径；指向仓库内容的实际 Markdown 链接仍会随分支更新。
